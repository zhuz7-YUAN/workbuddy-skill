# 每日招聘简报生成器

为求职者（典型：离校未就业毕业生）每日生成求职简报。任何人装了本 skill，跑一次首次引导后就能按自己的画像生成，不依赖特定会话、不依赖特定人。

## 首次使用引导（第一次必须做，之后的每日简报不需要重复）

**判断**：若本机没有 `config.json`（或用户明确说画像变了），**不要急着生成简报**，先主动开口引导，一次问清，问完把答案写入 `config.json` 再开工。引导要自然、口语化，不要一次抛十个问题（分 2-3 组问完即可）。

**必问清单**：

1. **简历**：「方便把简历发我吗？PDF/Word/图片都行。我只在本次会话里读它提炼技能关键词，帮你把岗位匹配做得更准。」
   - 用户发来后：解析简历，提炼「技能关键词 + 实习/项目经历 + 亮点与短板」，存进 `config.json` 的 `profile.resume_notes`。
   - 用户暂时不发：跳过，用问答补齐画像，后续随时可补。
2. **城市/地域**：「想留在哪个城市？只看本地，还是外地好机会也可以？」（决定 ✅ 标注口径，也决定源清单要不要换成本地站点）
3. **方向**：「想投什么方向？嵌入式/FPGA/芯片/硬件/机器人/软件测试……有偏好吗？」
4. **薪资期望**：「期望薪资大概什么范围？给个区间就行。」
5. **特殊要求（重要）**：「有没有硬性条件？比如不接受出差/夜班、通勤不能超过多久、只想去大公司或研究所、家在某地所以只想在某片区、身体状况或其他需要照顾的情况。有什么说什么，我好提前过滤。」
6. **邮箱（可选）**：「简报要不要每天发到你邮箱？不发也行，直接在这里看。」

**引导完成后**：把答案写入技能目录 `config.json`（格式见下），告诉用户「画像已就绪，明天开始每天 X 点给你出简报」，再继续生成当日简报。

> 隐私说明：简历和所有个人信息只在本机读取保存（`config.json` 仅落盘本机），**绝不上传、绝不含在分发包里**；简报正文也不出现证件号/住址等信息。

## 本机配置 `config.json`（含个人隐私，不要写进本 SKILL.md，也不要提交到任何仓库）

```json
{
  "name": "张三",
  "email": "zhangsan@example.com",
  "workdir": "D:/我的求职",
  "profile": {
    "city": "武汉",
    "degree": "2026届本科",
    "major": "电子与计算机工程(ECE)",
    "salary": "13-22K",
    "status": "离校未就业, 处于2年择业期(央国企按应届对待)",
    "directions": "嵌入式 / FPGA / 芯片半导体 / 硬件 / 机器人 / 央国企科技岗",
    "strategy": "央国企秋招主攻 + 中型上市公司社招补录 + 内推 + 外包兜底",
    "local_priority": "本地优先, 标注 ✅",
    "special_requirements": "不接受长期出差; 通勤1小时内; 优先研究所和有编制感觉的国企",
    "resume_notes": "技能: C/Python, STM32, Verilog, 有XX比赛项目; 短板: 无实习经历, 面试表达偏弱"
  }
}
```

关键字段说明：
- **`workdir`**：简报与清单文件的输出目录。缺省为当前工作目录。
- **`profile.city` / `profile.directions`**：清单页脚本会读它们生成个性化检索词。
- **换城市**：把 `scripts/sources.default.json` 里 `region` 为 `hubei`/`wuhan` 的条目替换成你所在城市的对应站点（人社厅、人事考试网、省级就业平台、本地重点高校就业网）。**各省结构高度相似，照着抄即可。**

找不到 `config.json` 时先跑「首次使用引导」；用户坚持跳过则回退到内置中性默认画像，保证开箱即用。

## 信息源策略（v2 核心，必须遵守）

**核心原则**：国企、事业单位、研究所、高校「只在官网发布」的岗位是第一优先；公开招聘平台（BOSS/猎聘/智联/前程/拉勾）降为**二级补充**（占岗位数 ≤40%）。

### 四条通道（按成本从低到高，依次尝试）

| 通道 | 适用 | 工具 |
|---|---|---|
| **A 静态直抓** | 普通 HTTP 就能读到内容的静态页 | `scripts/official_sources_scan.py` |
| **B AI 网页读取** | 直连会被拦（空包/断连），但 AI 的网页读取能力能读到 | 直接用 Agent 的 WebFetch |
| **C 动态渲染** | JS 渲染的 SPA，必须真浏览器跑一遍 | `scripts/spa_job_scrape.py`（Edge CDP，零安装） |
| **D 抓不到 → 给链接** | 上面三条都失败 | `scripts/official_sources_portal.py` |

**每天开工顺序（省时省积分的正确姿势）**：
```bash
# ① 静态源原始清单（秒级，先跑）
python scripts/official_sources_scan.py --md "$WORKDIR/官网原始清单_$(date +%F).md"

# ② 动态渲染源（较慢，每站约 20-30 秒；只抓与你方向相关的站，不要全跑）
python scripts/spa_job_scrape.py --only 国聘,本地高校 --md "$WORKDIR/深度岗位_$(date +%F).md"

# ③ 清单页（把抓不到的源变成可点链接，发给用户/自己用）
python scripts/official_sources_portal.py --out "$WORKDIR/官网直读清单.html"

# ④ 然后 AI 只做「筛岗 + 判断可投性 + 补充检索」，不要重复做机械抓取
```

要抓哪些源、用哪条通道，全部写在 **`scripts/sources.default.json`** 里（`channel` 字段四选一：`curl` / `webfetch` / `browser` / `manual`，另有 `search` 表示只能关键词检索）。**加新站就改这个文件，不用改代码。**

> `sources.default.json` v3（2026-10-05）共 27 个源，按 `type` 分类：
> 央企平台 / 国家级 / **军队系统** / 人社系统 / 地方国企 / 高校就业网 / 企业官网 / 官方官网 / 公开招聘平台 / 公众号。

### 军队系统源（极易遗漏，必须扫）——2026-10-05 新增

**这是最容易被整体漏掉的一整类岗位**：军队文职、直招军官/军士的公告**只发在军队人才网上**，
不投任何招聘平台，且常年半夜挂网。已实测 `curl` 可直抓，三源：

| 源 | URL | 覆盖 |
|---|---|---|
| 军队人才网·文职人员 | `http://81rc.81.cn/wzry/index.html` | 军队文职全国统考（含技术岗），报名 10-11 月、笔试 12 月 |
| 军队人才网·工作动态 | `http://81rc.81.cn/sy/gzdt_210283/index.html` | 各军种/部队**直招公告**（实测一次 33 条，含武警/火箭军/空军/海军/信息支援/网络空间/军事航天/联勤保障 2026-2027 直接选拔招录军官公告） |
| 中国征兵网 | `https://www.gfbzb.gov.cn` | 直招军士（理工科对口，本科可报） |

**各军种/战区没有统一列表页** → 用检索式补：`直招军官 2027 应届 <军种名>`、`军队文职 岗位 site:81rc.81.cn`、`军队文职 <城市> 岗位表`，命中即给原文链接。

一并补入的两类**地方事业编**源（`curl`）：`武汉市人社局`（市本级事业单位招聘）、各省人社厅「事业单位公开招聘」栏（湖北已有，另有广东作样板）。

### 通道 D 是硬性规则，不是可选项

对每一个「抓不到正文」的源，简报里**必须**交出两样东西，缺一不可：

1. **栏目直达 URL**（读者点开就是招聘列表）
2. **一键搜索链接**（`site:` 限定）：
   ```
   https://www.baidu.com/s?wd=site%3A<域名>+<关键词>
   ```
   例：`https://www.baidu.com/s?wd=site%3Acug.91wllm.cn%202027%20%E6%A0%A1%E5%9B%AD%E6%8B%9B%E8%81%98`

**并且要主动说明**：「这几个站我用程序读不到正文（动态加载），但链接是真的，你花 3 分钟点开看」。

**禁止的写法**：只写「该站需浏览器渲染」就完事 —— 那等于没交付。

### 用搜索引擎反查（对动态站特别有效）

搜索引擎往往已经把这些站的详情页收进索引了，即使页面本身是 JS 渲染的：

```
site:<目标域名> <关键词>        # 例：site:xsjy.whu.edu.cn 招聘
```

实测有效：能翻出高校就业网的岗位详情页（形如 `.../recruitmentinfo/show?recruitmentId=<32位id>`）、
以及央企在国聘的**独立子域名**（可直开，无需登录）。

**反例**：纯 SPA 且没有内页被收录的站（`site:` 查 0 条），只能给栏目入口让用户人工点——
这种要在简报里**明确标注"要靠你自己翻"**，不要假装拿到了。

## 通道 C 的四个坑（都踩过，照抄结论即可）

1. **必须加 `--disable-extensions`**。用户装的 Tampermonkey / 翻译插件会自动打开各自的欢迎页
   并排在 `/json/list` 前面，抢走"第一个标签"，导致抓回来的是插件官网内容而不是目标站。
   （`edge_cdp.js` 已内置过滤：跳过 `chrome-extension://` 与常见扩展站点，并按 `CDP_TAB` 关键词选标签。）
2. **`--user-data-dir` 必须独立且路径不含中文**，不要用用户日常 profile（会和已打开的浏览器争目录锁）。
   **别占用 9222**——很容易被用户其它带登录态的会话占着；默认用 9444。
3. **进程驻留**：用 shell 的 `&` 起的 Edge 会随 shell 结束被回收，端口随即失联。
   必须用 detached 方式（`spa_job_scrape.py` 已用 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`）。
4. **无头模式冷启动要等 8–12 秒**再探测，比有头模式慢。

> 抓取前请确认目标站点允许抓取（看它的 `robots.txt`）。只抓公开信息、低频、不登录、不绕过付费墙。
> **不要去逆向需要登录令牌的接口**（既越界也没必要——搜索引擎与子域名通常已经够用）。

## 扩面原则与档位排序（2026-10-05 新增，**优先级高于 `profile.directions`**）

**背景**：用户（家属）明确要求——**投递方向不要卡死在某一两个方向上**。求职者要求已降到最低：
只要能找到工作、只要专业沾得上、只要岗位要求与专业相符，**都想投、都去碰运气**。

**执行口径：`directions` 只决定「排序优先级」，不决定「收不收」。**

| 档 | 定义 | 在简报里的位置 |
|---|---|---|
| **A 档** | 专业完全对口、学历/届别基本能过 | 排最前，进「今日必投」表 |
| **B 档** | 沾边、专业沾得上，可能要碰运气 | 一并收录，**不许因为"不是本方向"就丢掉** |
| **C 档** | 有硬门槛（政审 / 体检 / 专业目录 / 届别卡死） | 收录但标 🔒 + 注明"投前须先核条件" |

- **数量优先于精选**：宁可多列让求职者自己挑，也不能因"不够纯"而漏掉能投的岗。
- 唯一仍要剔除：与专业**完全无关**的岗位（纯语言、教师、客服、销售、金融业务、行政等）。
- 与「宁缺毋滥」的关系：那一条针对的是**凑数灌水**；**扩面本身不是灌水**——区别在于每条是否真实可投、是否标注了可投性判断。

## 截止时间前置提醒（2026-10-05 新增，强制）

岗位信息「干巴巴」最大的问题不是缺岗位，而是**错过了报名窗口**。因此：

1. 每条岗位必须写「**报名/投递截止日**」或「**招满即止**」；
   列表页没有截止日的，必须写「公告未标截止，须点开原文核」，**不许留空**。
2. 距今天 **7 天内到期**的，岗位名前加 **⏰**，并在「今日必投 5 条」表下方单独列一块「**⏰ 本周倒计时**」。
3. **现场宣讲会 / 双选会日期按硬节点列出**，格式如 `10-08 14:30 武汉理工 中航光电宣讲会`，
   并附一句"带纸质简历直接去，比网投快"——**这类最容易因为"忘了"而错过，且现场转化率远高于网投**。
4. 线上双选会有明确活动区间的（如「9-03 至 10-31」），写清起止日。
5. **军队直招公告**这类列表页不给截止日的，**必须提示"报名窗口通常只有 10-20 天，务必点开原文核截止时间"**。

## 简报结构（9 段，固定顺序，不可省略）

0. **今日必投 5 条**（置顶表格：单位 | 岗位 | 为什么是它 | 投递方式）——5 分钟知道今天干什么
   **紧接表格下方加「⏰ 本周倒计时」小块**：列出 7 天内到期的报名/投递截止日 + 现场宣讲会/双选会日期（见上节）
1. **开场**：称呼「{name}同学」，一句当日行情 + 一句结合情境的鼓励
2. **真实牌面盘点**（表格）：身份有效性、城市、时间窗口、本方向真实短板
3. **本地优先 ✅**：{city}本地岗位，逐条标 ✅，含单位/岗位/薪资/门槛，重点岗标匹配点
4. **央国企 / 事业单位 / 银行科技岗**：强调应届身份是否有效 + 报名截止提醒（**这类最常出现在官网**）
5. **专业方向岗**（按 `profile.directions` 分列）：本方向主攻岗位
6. **今日简历怎么改 / 补强动作**：给 3-4 条具体动作，写成能直接抄进简历的措辞
7. **今日雷区表**（4-6 条）+ **多渠道行动方案**
8. **回血段 + 今日作业清单**（6-8 条可勾选）
9. **官网直查区**（v2 新增，硬性）：
   列 3-6 个「我只找到了地址、你点开自己读」的源，每条给：
   单位/网站名 ｜ 为什么值得看 ｜ **可点击的直达链接** ｜ **一键搜索链接**
   并加一句「这几个站我用程序读不到正文（动态加载），但链接是真的，你花 3 分钟点开看」。
   数量控制在 3-6 条，别把清单全堆上去淹没信息。

> 每条岗位必须标注**来源类型**：官方官网 / 高校就业网 / 人社系统 / 央企平台 / 招聘平台 / 公众号。
> 官方来源的岗位排在表格最前。

## 行文基调（硬性，与岗位数据同等重要）

简报的读者是一个正在找工作、可能有点焦虑的年轻人（或替孩子操心的家长）。**纯信息罗列是不合格的**：

1. **开场一句暖心话**：不是空话鸡汤，而是结合当日情境。例如连续几天没面试邀约时写「投出去的简历没有回音，不一定是你的问题——8 月底正是 HR 筛简历堆积期，坚持投，9 月第一周是回复高峰」。
2. **每段穿插小贴士/注意事项/小提醒**（至少 2-3 处，位置自然，用引用块 `>` 或 💡 标出）：
   - 干货型：网申填表技巧、简历关键词怎么改才能过机器筛、央国企报名截止规律；
   - 避坑型：外包驻场身份、试用期辞退率、培训贷骗局、**「实习岗」卡在校生身份（已毕业投了必被拒）**；
   - 打气型：数据化鼓励（本周已覆盖 N 家、按转化率估算下周约 X 个笔试）。
3. **岗位针对性**：有 `resume_notes` 时，重点岗位标注匹配点；明显不匹配的宁可不放，**不凑数**。
4. **尊重特殊要求**：`special_requirements` 里的硬性条件严格过滤，拿不准的标提醒。
5. **结尾行动建议 + 一句打气收尾**：先给今天该投哪几家的明确清单，再真诚收尾（禁止空洞口号）。

**两条可信度红线**：
- **严禁编造岗位**。搜不到就如实说明数量不足，不要用想象补。
- **回血段禁止编造「某某学长」的个案**——编出来的案例一眼看穿，反而失去信任。
  正确做法：引用**当天真实抓到的 JD 原文**（如「无实战经验也可」「课程设计即可算经验」），
  或用**匿名类型化描述 + 一句"他的关键动作是……"**，让案例直接变成今天能照做的动作。

## 去重规则（硬性）

- 生成前**必须先读昨日简报**（`workdir` 下 `招聘简报_YYYY-MM-DD.md`，按日期往前找最新一份）。
- 提取昨日全部单位+岗位，剔除完全重复项；昨日重点未投岗转入复推段。
- 同一单位**不同岗位/不同城市/不同渠道**算新条目，可以再投。
- 过期的硬节点要**主动声明关闭**，别每天重复提醒。
- 若同时跑多个方向（多份简报并行），**后跑的要读当日已生成的其他方向简报**，避免同一天推同一家单位两次。

## 邮件发送

- 收件与主题从 `config.json` 的 `email` 读取，主题形如 `【每日求职推荐】{city} - YYYY-MM-DD`。
- **优先**用可用的邮件工具（如 Agent Mail connector）。
- **无人值守的自动化会话里，MCP 邮件工具常常不可用**（报 `not found in the deferred tools index`）。
  此时改用**本机 SMTP 脚本**（如果你有配）：验证成功以脚本输出为准；失败重试不超过 2 次，
  仍失败则降级为本地 `present_files` 交付 markdown，并在日志里写清报错原文。
- ⚠️ **QQ 邮箱 SMTP 直发不会进「已发送」文件夹**，不能靠查发件箱验证是否发出；
  只能看脚本成功输出，或查收件箱有无退信。
- ⚠️ **抄送（CC）必须显式加，否则只发到 `--to`**：本机 `send_mail.py` 支持 `--cc`，
  信封收件人会自动并入 CC 地址（缺这一步 SMTP 只按 To 投递，CC 形同虚设）。
  多方向并行时，若「求职者本人」和「委托人/家长」都要收，命令里两处都写：
  ```bash
  python send_mail.py --to <求职者邮箱> --cc <委托人邮箱> --subject "..." --file 简报.md --html
  ```

## 执行流程（AI 被加载后立即跑，不要等追问）

1. **读 `config.json`**：不存在则先走「首次使用引导」，写好 config 再继续。
2. **跑脚本拿原始清单**（按上面「每天开工顺序」①②③）：
   - `official_sources_scan.py` → 静态官网原始清单
   - `spa_job_scrape.py --only <相关站>` → 动态渲染站的深度岗位
   - `official_sources_portal.py` → 可点清单页（给抓不到的源兜底）
3. 用 WebFetch 补通道 B 的源；用检索补二级平台的缺口。
4. 按画像 + 特殊要求 + 简历技能关键词筛岗，**官方来源优先、本地优先、宁缺毋滥**。
5. 按 9 段结构 + 行文基调撰写正文，落盘：
   ```bash
   python scripts/gen_brief.py --date YYYY-MM-DD --raw-file 草稿.md --out "招聘简报_YYYY-MM-DD.md"
   # 或用结构化数据：python scripts/gen_brief.py --date YYYY-MM-DD --data brief.json
   ```
6. 本地 `present_files` 交付；邮件通道可用则发邮件。
7. 调 `scripts/usage_logger.py` 的 `log_event(...)` 在本机记一条运行日志（仅落盘，不上传）。

## 目录结构

```
job-brief-generator/
├── SKILL.md
├── config.json                      # 本机个人画像（含隐私，不提交）
├── scripts/
│   ├── gen_brief.py                 # 简报落盘
│   ├── usage_logger.py              # 本机运行日志
│   ├── sources.default.json         # ★信息源清单（四通道模型，改这里加站）
│   ├── official_sources_scan.py     # 通道 A：静态直抓
│   ├── official_sources_portal.py   # 通道 D：生成可点清单页
│   ├── spa_job_scrape.py            # 通道 C：Edge CDP 动态渲染
│   └── edge_cdp.js                  # 通道 C 的 CDP 客户端（Node，零依赖）
└── references/                      # （可选）你自己的城市源清单
```

## 何时用

- 用户说「生成今天的求职简报」「帮我儿子找武汉工作」「每日招聘推荐」「官网招聘信息抓不到怎么办」。
- 配合自动化：在 WorkBuddy 建每日定时任务，prompt 写「调用 job-brief-generator 生成今日简报并发邮件」。
  多个方向并行时**错开发送时间**（如 8:00 / 8:25 / 8:50），避免邮件通道同时发信冲突。

## 依赖

- **Python 3.8+ 标准库**（三个抓取脚本零第三方依赖）。
- **Node.js 18+**（仅通道 C 需要；用其自带全局 `WebSocket`）。
- **Microsoft Edge**（仅通道 C 需要；Windows 自带。不下载 Chromium）。
- Agent 的联网能力（WebFetch / WebSearch）用于通道 B 与补充检索。
- 可选：邮件 connector，或本机 SMTP 脚本。

## 免责与边界（写给使用者）

- **「把所有官网岗位全部抓取到位」是做不到的**。企业官网大量是 JS 动态渲染，需逐个渲染，
  成本与覆盖面都是硬约束。本 skill 能做到的是：**把已验证可抓的官方源做成每日必扫，
  覆盖国企/事业单位的主干渠道**，并把抓不到的源转成「可点链接」交给你。
- 抓取请遵守目标站点的 `robots.txt` 与使用条款；只取公开信息、低频、不登录、不绕过任何访问控制。
- 简报是**信息辅助**，岗位是否可投、截止时间、届别口径**一律以官方公告原文为准**。
  推荐任何央企/事业单位岗位前，务必打开**官方公告原文**核对「招聘对象」与「报名截止时间」两处
  （第三方转载经常把届别门槛简写掉或整段删除）。
