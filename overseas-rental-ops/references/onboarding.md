# 初始化访谈：先问清"谁住 / 谁办 / 用什么邮箱 / 要不要抄送"

## 为什么这一步必须排在第一位

技能原本默认 **租客 = 用户 = 同一人**。现实里这个假设经常是错的：

- 父母给子女租（最常见）
- 朋友/亲戚代办
- 学长帮学弟找

一旦是**代租**，五件事同时变了：

| 变了什么 | 后果（不做这一步会怎样） |
|---|---|
| 发信人 ≠ 租客 | 署名写成租客本人 = 替本人发信，房东按你的承诺追责会追到孩子头上 |
| 需要"发件箱" | 用孩子的邮箱发，既打扰她、又让回复散落在她不常用的邮箱里 |
| 需要"回复收件箱" | 回复散落 = 同一件事被问两遍 = 重复谈判 |
| 需要**抄送第三人** | 家长想知道进度，只能反复问孩子，孩子也烦 |
| **抄送不能无脑抄** | 把未核实的假消息/僵尸房源直接抄过去 = 把筛选成本转嫁给家人 |

最后一条是这套东西最容易做错的地方，也是本文件最值钱的部分。

## 访谈提纲（四组，一次问完）

### A 组 · 谁住（合同主体，必须准）

| 问 | 为什么 |
|---|---|
| 租客姓名？**护照上的拼写**是什么？ | 合同、注册、居留全用它。拼写错会一路炸 |
| 签证/身份类型？（学生签、交换、工作） | 决定担保可行性与房东的接受度 |
| 性别？接受同性/异性合租吗？ | 很多房源有性别限制，问询必须一次问对 |
| 学校全称 + 院系（当地语言 + 英文） | 这是给房东最有力的可信度证明 |
| 在当地的常用语言？ | 决定用哪种语言的问询模板 |

### B 组 · 谁办（决定署名与口吻）

| 问 | 为什么 |
|---|---|
| 是你自己租，还是帮别人租？ | 决定 `_role.relation` |
| 代办人的姓名与与租客的关系？（父亲/母亲/朋友/中介） | 决定 `sender_name` 与署名口吻 |

**口吻规则**：邮件类（问询/追问）用**委托人第一人称**（"我代 XX 写这封信"）；
群帖/私信/站内信是**租客本人**发的，用租客第一人称。两套不能混用。

### C 组 · 邮件链路（这是用户强调的重点）

| 问 | 建议 | 为什么 |
|---|---|---|
| **发件箱用哪一个？** | 用**委托人的**邮箱，不要用租客的 | ① 不打扰本人 ② 口吻对 ③ 所有回复集中一处 ④ 租客邮箱常不常用 |
| **署名写什么？** | 写代办人姓名，或"XX 的家人" | 房东要知道在跟谁谈。写成租客本人＝替本人承诺 |
| **回复收哪里？**（reply-to） | 默认＝发件箱；也可指定别的 | 集中管理，避免同一房东被问两遍 |
| **要不要抄送第三人？** | 见下 | 进度同步，但必须有策略 |
| **抄送策略选哪档？** | **`confirmed_only`（强烈推荐）** | 见下 |

#### 抄送三档怎么选

| 档位 | 行为 | 什么时候用 |
|---|---|---|
| `none` | 不抄送 | 自租，或不需要别人知道 |
| **`confirmed_only`** | **只把【已核实可租】的房源抄给第三人** | **默认推荐。** 家长的诉求是"知道进度"，不是"看你搬砖" |
| `all` | 每条原始房源都抄 | ⚠️ 慎用。会把未核实的假消息一起抄过去 |

**为什么推荐 `confirmed_only`**：假设一天抓 30 条、其中 18 条是旧的或占用的，
`all` 就是把 18 条噪音抄给家人，家人再去逐条看 —— 这就是"浪费女儿时间"那个坑的翻版。
`confirmed_only` 保证：**抄过去的一定是已经核实过、现在真的能租的。**

**技术上怎么保证它不被绕过**：`outreach.py` 里，`cc_mode=confirmed_only` 时
**必须显式加 `--confirmed`** 才会抄送第三人；否则只发房东、不抄送，并在输出里说明原因。

```bash
# 房源尚未核实 → 不抄送（默认行为，安全）
python scripts/outreach.py --profile renter.json --stage first_contact --lang it
#  抄送：（无）
#        └ cc_mode=confirmed_only，但未加 --confirmed → 本封不抄送第三人

# 已在核验层确认可租 → 放行抄送
python scripts/outreach.py --profile renter.json --stage first_contact --lang it --confirmed
#  抄送：your_family@example.com
#        └ cc_mode=confirmed_only + --confirmed（已核实，放行抄送）
```

### D 组 · 目标（喂给核验层）

| 问 | 为什么 |
|---|---|
| 目标城市 + **允许的邮编** | 房源板常覆盖整个省，没邮编会把 25 公里外的房子混进来 |
| **工作/学习地点在哪？**（学校主楼 / 院系 / 实习公司，给全地址） | **决定"通勤"这一列。** 房子在不在城市内只是粗筛；真正决定"值不值"的是它到你每天要去的地方多远、要多久。没有这个地址，commute.py 算不出任何距离 |
| 通勤方式偏好？（步行 / 骑车 / 公交） | 决定 commute 以哪种方式给出时间。意大利学生常靠步行+公交 |
| 预算（按**月总成本**，不是租金） | 意大利学生房杂费常 €80–150/月，只看租金低估 30–45% |
| 租期起止 | 短租是本场景的核心约束 |
| 可接受的性别/身份限制 | 问询第一封就要问对 |

> **为什么"工作/学习地点"是必问项而不是可选项**：同一座城市里，两个都"在 Trento"的房子，
> 到大学主楼可能是 10 分钟步行，也可能是 35 分钟外加换乘。只报"城市"等于没筛。
> 把地点写进 `_target.work_place`，`commute.py enrich` 才能在每条房源上补出
> **直线/骑行公里数 + 步行时间 + 最近公交/火车站距离**。

## 常见错误（onboard.py check 会抓）

| 错误 | 为什么错 |
|---|---|
| 用租客邮箱当发件箱 | 打扰本人 + 回复散落 + 用孩子的账号替她承诺 |
| 代租但 `sender_name` 留空 | 系统回退成租客名 → 署名变成孩子本人 |
| `cc_mode=all` | 未核实的房源直送第三人，重演"假消息浪费家人时间" |
| `cc_mode=confirmed_only` 但抄送对象为空 | 策略标了却没用上 |
| 只填城市不填邮编 | 核验层无法分流 |

## 用法

```bash
python scripts/onboard.py init  --out renter.json     # 生成模板
# 按上面四组问题逐项填（AI 会先访谈你）
python scripts/onboard.py check --file renter.json     # 校验必填与常见错误
python scripts/onboard.py show  --file renter.json     # 打印"谁—发—收—抄"一张表
```

`show` 的输出示例：

```
租客（住的人）      ：<委托人> / ZHU Zhiqi（F）
                    Università di Trento  Facoltà di Economia
委托人（办这事的人）：用户（父亲）
模式                ：代租（relation=father）

── 邮件链路 ──
发件箱              ：your_sender@qq.com
发信署名            ：Zhu Hengfeng
回信收件（reply-to） ：your_sender@qq.com
抄送对象            ：<委托人> <your_family@example.com> [all]
抄送策略            ：confirmed_only —— 只把【已核实可租】的房源抄给第三人（推荐）
```

**这张表就是整个流程的"抬头"**：后面每一步（核验、问询、抄送、台账）都以它为准。
`renter.json` 含家庭信息与邮箱，**不要提交到仓库、不要随技能包分发**。
